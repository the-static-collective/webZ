# CIRCUIT 006 — First human-operated crossing field kit

**Status:** review-only, deliberately unmerged. The code offers a practical **two-person, two-computer field procedure**; running it in GitHub Actions only simulates operator choices on one CI runner. No real field trial, authenticated identity, real gathering, payment, project approval or device separation is claimed.

## What 006 adds beyond 005

The real native donor sequence remains unchanged:

Revival OSHB v2.2 Genesis 1:1–3 → GHoT hash → reLATTE signed source envelope → two sovereign receiver receipts → source verifies the signed return.

006 adds operator-local steps that the earlier CI specimen did not have:

- **Independent key enrollment:** Receiver B confirms the full SHA-256 public-key fingerprint with source A **in person or over a live, independently authenticated call** and stores the source public key *outside* the offered-files folder. The script refuses an altered fingerprint. It records only the operator's self-attested enrollment; it cannot authenticate the person.
- **Explicit receiving choice:** B must use an interactive console to type **HOLD** or **REFUSE** after inspecting the real attributed source. The code provides no ADMIT, DEPLOY, SEND, MONEY or PUBLISH action. In CI, test-only choices require an explicit `--synthetic-ci` flag and are recorded as simulations.
- **Separate native receipt export:** B creates a new local receiving key and signed reLATTE RECEIVE, R3_HOLD/R3_REFUSE and payload-custody receipts. B transfers **only** the portable `RETURN_ONLY_THIS_FILE.json` to A.
- **Independent return verification:** A confirms B's public-key fingerprint on another trusted channel and checks the exact source crossing, reLATTE signatures, native receiver identity, exact byte hash, HOLD/REFUSE choice and matching signed custody claims. A cannot verify physical custody or the human's identity merely from the return.

## Software requirements

- Two **independently operated** computers, or two isolated computing environments for a *practice only* session. The genuine field proof requires two real machines and willing human operators.
- Git, Python 3.11+, Node.js 22+, local file transfer (USB/AirDrop or equivalent).
- A checkout of webZ Circuit 006 plus the exact donor commit SHAs below. On each computer, install reLATTE's declared dependency with `npm install --ignore-scripts --no-save --no-package-lock --omit=dev` inside the pinned donor directory. The donor commit contains no package lock.
- A legitimate out-of-band way to establish **full** fingerprints; never trust a fingerprint solely because it arrived in the same folder as an offer.

**Mac note:** The 2012 MacBook running macOS Mojave is not a verified Node 22 runtime. This is NOT advertised as a click-once Mojave app. Use compatible computers for the native cryptographic ceremony. The standalone Circuit 001 offline HTML remains a different, browser-only local demonstration.

## Two-computer operator card

All paths below are examples. On **A**, prepare an offer with the original 005 source:

```sh
python3 pilots/abundent-circuit-001/crossing-005/source_005.py --revival ../revival --ghot ../GHoT --prepare ./candidate.json
node --experimental-strip-types pilots/abundent-circuit-001/crossing-005/crossing_005.mjs issue --relatte ../reLATTE --candidate ./candidate.json --out ./source-offer
node --experimental-strip-types pilots/abundent-circuit-001/crossing-006/field_006.mjs fingerprint --key ./source-offer/source-public-key.json
```

A tells B the **full fingerprint directly by the trusted independent channel**. Copy the three *public, bounded* offer files (`source-payload.json`, `signed-crossing.json`, `source-public-key.json`) from A to B; no private key leaves A. The signing key generated by 005 is an ephemeral demonstration key, not a durable human credential.

On **B**, save the offer folder separately from a private trust folder, and verify that the fingerprint shown on A matches B's received public key. Replace `sha256:FULL_HEX_FINGERPRINT_FROM_A` with the entire fingerprint that A confirmed independently:

```sh
node --experimental-strip-types pilots/abundent-circuit-001/crossing-006/field_006.mjs enroll --key ./received-offer/source-public-key.json --confirm-fingerprint 'sha256:FULL_HEX_FINGERPRINT_FROM_A' --channel live-call --trust-dir ./my-private-trust
```

The program requires B to type `ENROLL` interactively. B then checks the real source, attribution, and choice. B uses:

```sh
node --experimental-strip-types pilots/abundent-circuit-001/crossing-006/field_006.mjs receive --relatte ../reLATTE --revival ../revival --offer ./received-offer --trust-dir ./my-private-trust --receiver ./my-private-receiver
```

The program requires B to type **HOLD** or **REFUSE**; it cannot admit a project. It prints B's new, locally generated public-key fingerprint. B tells A the full fingerprint via the independent channel, then sends **only**:

`my-private-receiver/RETURN_ONLY_THIS_FILE.json`

On **A**, after independently confirming B's full fingerprint, verify the returned signed claims:

```sh
node --experimental-strip-types pilots/abundent-circuit-001/crossing-006/field_006.mjs verify-return --relatte ../reLATTE --revival ../revival --offer ./source-offer --return ./RETURN_ONLY_THIS_FILE.json --expected-receiver-fingerprint 'sha256:FULL_HEX_FINGERPRINT_FROM_B'
```

Do not copy, upload, sync or publicly publish `my-private-trust`, `my-private-receiver`, `receiver-key.json`, private journals, private material, or personally identifying event records. The example project data is **public source text only**.

## Evidence criteria for a *real* first crossing

Record only non-sensitive facts: whether A and B used genuinely separate physical computers; whether each independently confirmed the other key fingerprint over a separate channel; whether B consciously selected HOLD or REFUSE; whether A verified the returned reLATTE receipts; whether any data had to be re-entered after a cold restart. Do not label these claims verified until the human operators have supplied evidence they actually observed. CI passing is **not** a real human trial.

**Remaining limitations:** user input is self-attested; a caller can automate the console; 005 uses a fresh signer per offer rather than durable owner-owned identity; the receiver's private JWK is stored in a permission-restricted local file without encryption-at-rest; the source trusts B's signed custody statement but cannot independently inspect physical retention; no automatic networking or identity directory exists. The original Circuit social UI remains separate from this cryptographic field procedure. No production deployment or native Full Measure write occurs.

The next milestone is to carry out this procedure on two compatible **physical** devices, independently record evidence, and only afterward propose a separate optional real-world Fellowship planning project.
