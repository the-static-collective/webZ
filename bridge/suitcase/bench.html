PHONE-FIRST / OFFLINE-FIRST

Goal: one ordinary reusable physical suitcase that survives loss of internet and preserves independent, signed, public-safe founding records. The first bench build is not a mesh network, a safe private messenger, a legal organization or a deployed service. It needs no soldering, Linux flashing, LoRa transmitter or central server.

00 / PREPARE THE BENCH

Put these on the table before mounting anything. Use the substitute available; do not purchase a special enclosure merely for the first dry run.

□ Dry case / tool box / briefcase   □ Working maintained Android phone or other browser device   □ Intact certified power bank + approved USB cable   □ Printed founding cards or blank paper   □ File-sharing option (Bluetooth/USB/removable drive)   □ Optional second independently controlled device.

Stop conditions: swollen, leaking, punctured, visibly damaged or overheating battery; exposed mains wiring; uncertain charging circuit; case pinching cables or crushing a device. Do not solder, reconstruct or rewire a lithium pack. Do not connect salvaged solar panels directly to a phone or battery unless through an appropriate, compatible regulated charger. Do not charge a device inside a sealed, unventilated case. Disconnect malfunctioning equipment.

01 / PHYSICAL LAYOUT · NOTHING PERMANENT YET

Place paper in one side of the case and the phone in the other, with space for airflow and cable removal. Secure components only with reversible nonconductive restraints that do not cover vents or buttons. Keep USB ports accessible and ensure the lid closes without force. Check that nothing shifts against the screen or power-bank connectors. Perform the software test with the case open before making a permanent mount.

02 / INSTALL THE OFFLINE SHELL, ONCE WHILE CONNECTED

On the device, open The Suitcase Internet over HTTPS while online. On Android Chrome, use the browser menu's Install app or Add to Home screen option if offered; this is convenient but not required. Allow an initial visit and a reload so the service worker can cache the public application shell. Do not clear browser site data afterward: that also risks destroying the private signing key.

Then turn mobile data and internet Wi-Fi access off, or enable airplane mode. If you will transfer a file by Bluetooth or a local Wi-Fi radio, explicitly re-enable just that radio without connecting to the internet. Close/reopen or reload the page. The title, forms and local rooms should still appear. Test this before trusting the case.

□ App loaded online □ Reloaded □ Opened/reloaded without internet □ Local storage persisted. If offline fails, reconnect once, revisit the exact app URL, reload, confirm the app was stored, and repeat. A brand-new device cannot fetch this page for the first time without internet or a separately provided local server; this version does not provide a hotspot server.

04 / GIVE A SECOND DEVICE ITS OWN KEY · PHONE B

On another device, install/cache the same public app while internet is available, then test it offline. Its holder creates a different room and key. Transfer Phone A's SEED JSON intentionally as a file (USB, direct device file transfer or another approved path). On B, import the signed JSON and check the issuer fingerprint out-of-band against A's paper record.

At 06 / Found an Independent Room, select B's own room, choose the imported seed, write a public-safe purpose and locally chosen operating rules, explicitly accept, then sign a GENESIS. Download this signed GENESIS JSON and give it to A for verification. On B, optionally publish a fictional opt-in CAPABILITY and share that signed file with A too.

Independence boundary: two devices operated by the same person demonstrate separate cryptographic keys, not independently governed organizations. To claim NODE ALIVE, a second consenting actual operator must exercise their own authority, independent storage and right to refuse.

05 / REQUEST → REFUSAL → RETURN

A imports B's public-safe CAPABILITY. In the local directory, tap Address an OFFER to this key, fill in a fictional offer and sign it. Transfer its JSON to B. B imports, checks it, chooses REFUSE, signs a DISPOSITION and transfers it back to A. A imports it and checks that the response cryptographically references the offer. Neither the initial offer nor REFUSE grants physical services, access, affiliation or legal status.

□ Offer signed by A □ Imported by B □ REFUSE signed by B □ Response imported by A □ Response matches exact offer digest □ Refusal respected.

06 / LOSS-OF-NETWORK TEST

While internet is still disabled, restart/reopen both app sessions. Verify that each retains its own locally stored key and the signed packets imported so far. Repeat viewing the refused offer. Confirm both devices can still display founding cards, especially the print fallback. Never erase storage to “test recovery”: current key recovery does not exist.

□ Device A restarted offline □ Device B restarted offline □ Signed records readable on both □ No HTTP relay needed for the file handoff.

08 / NEXT HARDWARE GATE, NOT PART OF TODAY'S BUILD

To let a brand-new phone connect without prior internet, a subsequent prototype needs a local HTTP(S) server on an approved spare computer/router, and a tested secure-origin installation path. The current static Suitcase uses the first online load to install its offline shell. The Linux boot/install composer and optional Reticulum/Meshtastic transports remain separate future modules; no receive-only radio is assumed capable of transmission. Do not wire power distribution or transmit until equipment-specific safety and radio compliance are known.

First actual deliverable: a physical case, a running offline-capable phone, a signed seed, an independent signed response and a recorded refusal. For the full NODE ALIVE claim, independently witnessed physical operation and real human governance are still necessary.
