# WEAVING GARDEN 002 — A portable question, independent return

**Source:** webZ / Abundent `/weave/`, stacked on [WEAVING GARDEN 001](https://github.com/the-static-collective/webZ/pull/88). A reviewed, local-source experiment; no production release or partner enrollment implied.

## What the public visitor can actually do

1. Write a deidentified need, offer, and small suggested experiment.
2. Create a public share link for **those three fields only** (existing 001 behavior).
3. Optionally write one 14–140-character public-safe question, check a self-review box, and explicitly download `abundent.weaving-handoff/v0` JSON.
4. A separate source-owner can later decide whether to consider it. **This page does not send or route it.**
5. Private observations remain a separate download, never in either public link or handoff file.

The `handoff.mjs` producer verifies the exact shape and a domain-separated SHA-256. A content hash is not human consent, a signature, enrollment, a real recipient or fulfillment. The question record is purposefully **not** `circulation.field-question/v0`: that donor contract is bound to one historic October 24, 2026 event. General Weaving Garden visitors cannot claim that event by clicking a button.

1. `webZ` public `handoff.mjs` and original `CIRCULATION-003` `packet.mjs`, loaded at a fixed external source SHA;
2. `CANNON` independent CIRCULATION-003 Python source validator issuing `HOLD_UNPUBLISHED`;
3. Original `CANNON CIRCULATION-001` fictional seed compiler → original `Free Graph` content-addressed packet and cold verification;
4. Original `planZ` compiler returning separate **synthetic** CARE and CULTURE responses;
5. Original `CANNON` return-to-graph with immutable source history, native graph validation, and independent assertions binding the **same literal fictional question** across all stages.

The CANNON CIRCULATION-001 seed **requires fictional input** and is never fed genuine browser exports. An actual human opportunity is not automatically turned into a `FICTIONAL` graph. This executable lab proves *interface compatibility only*, not that a real person gave permission or that a receiving organization considered the candidate.

The workflow explicitly checks out each external donor at its pinned commit, invokes their original scripts, verifies original outputs separately, and publishes **no human data**. No credentials, calls, emails, payments, messages, attendees, or real-world work.

## Human gating before any future real circulation

- Secure **specific human permission** for the exact deidentified words; preserve refusal and withdrawal.
- Seek **independent steward/source-owner review**, not merely local checkbox selection.
- Resolve the distinction between general-purpose questions and the historical event-scoped CIRCULATION-003 contract.
- Require each receiving organization's separate choice and independently attested result.
- Maintain recipient-owned records and a correction or deletion path. Only then consider a server-side routing service.
