**Implemented source:** `bridge/network/` in webZ. **Status:** read-only candidate mapping, **not** an institutional relationship or delivered application. Owner approval, a real reply, and independent field proof remain outstanding.

## What changed on 2026-10-28

The existing nine `BRIDGE-001` prospective doors remain source-owned in `bridge/model.mjs`. This extension adds fourteen additional opportunities/community doors, yielding **23 prospects**. The original manifest `bridge/bridge-proposal-v0.json` is retained as a dated nine-room artifact, **not misrepresented as the current atlas**.

`bridge/network/model.mjs` derives a single in-memory institutional atlas from both sets. It models **nine source-owned project capabilities** and explicit `POTENTIAL_CAPABILITY_FIT` edges. Each edge means an operator could investigate an application fit: it does **not** describe an actual contact between institutions, a partnership, applicant eligibility or delivered effect.

The `bridge/network/` page shows a filterable room list, a keyboard-operable SVG graph, official program links, deadline snapshots, entry gate, specific ask, proposed components and immediate human task. From a selected room it computes other prospective **stepstones** based on capability overlap; similarity is not an introduction. It exports:
- `abundent/bridge-institutional-atlas-v1`: all 23 public candidates, nine internal organs and prospect-to-organ fit edges. Explicit partner/submission/verification counts = 0 *claimed by this software*.
- `abundent/bridge-institutional-dossier-v1`: one prospective room, a human-gated review checklist, separate hypothetical adjacency, original source, unsent draft letter and `NOT_SUBMITTED / NOT_ESTABLISHED / NOT_VERIFIED` claims.
- The existing `abundent/bridge-invitation-v0` from each room, still explicitly `DRAFT_NOT_SENT`.

Nothing is submitted, published to a database, emailed, signed, accepted, dispatched, or fetched by the new page. No third-party identities are indexed and no credentials or resident records enter these exports.

## Stepping stones and cross-system architecture

Example conceptual route: `The Garden → Nexus` (local learning team permission) → `Jubilee → Levitt` (eligible nonprofit concert organizer) → `Open Referral` (technical critique) → `Code for America` (selected demo). **No stage currently proves admission to any other stage.**

JAR;VIS can *later* read the exported manifest and propose one bounded preparation task; planZ can track owner-approved applications and gaps; reLATTE may transport a separately signed invitation to an independently owned receiver; GRAFT can compose a source-pinned specimen; the Link Wallet can custody real private capabilities. These remain **owner-local and unintegrated by this atlas**. In particular: `CONNECTS_CANDIDATE != RELATIONSHIP`, `APPLICATION != AWARD`, `REPORTED != VERIFIED`.

## Actual field gate

1. Verify eligibility, target mission, current deadline and official primary source.
2. Obtain the explicit permission of a real applicant, host or project owner and choose **one** non-sensitive, nonurgent work item.
3. Build an accurately scoped reviewable demo with source SHA and licensing review.
4. Ask one potential recipient for review only after a human inspects and separately authorizes contact.
5. Store any genuine submission acknowledgement or disposition in an authorized receiver, not in the candidate map.
6. Require an independently accepted result before changing the nature of a claimed relationship or outcome.
7. Document rejections, withdrawals and missing responses; do not inflate the successful-network count.
