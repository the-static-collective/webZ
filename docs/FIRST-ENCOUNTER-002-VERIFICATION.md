## What is executable

`/encounter/` and `scripts/inspect-encounter.mjs` independently inspect a public signed webZ invitation, native reLATTE v0 proposal, exact public text, and optional native response. Expected source/receiver worlds, particulars, key fingerprints, HTTPS origin, revocation knowledge and verification cut are supplied separately. Loading records never executes, admits, or delivers them. Explicit pin acceptance precedes browser verification; changing inputs invalidates the accepted observation.

The output is a deterministic **observation**, not a sovereign journal, authorization service, or transport receipt. It always declares network delivery disabled, authenticated transport/two-device encounter/human action UNOBSERVED, both independent histories NOT_ACQUIRED, publication permission NOT_GRANTED, and no world history write. A current local revocation or expired invitation blocks an unreturned proposal but does not erase an already signed historical disposition. Time and revocation provenance remain caller supplied.

The protocol profile is deliberately founding and bounded: text/plain, 2048 UTF-8 bytes, one payload reference, no ancestral parents, inspection-only rights, receiver-local candidate effect. Native v0 contracts remain reLATTE-owned. webZ's invitation ID/signature use distinct domain separators. A response bundle has outer content integrity and **two individually signed native receipts**; webZ does not invent an outer receipt signature.

## Evidence and validation

- All unit tests, the complete existing offline mobile/desktop/cache/privacy suite, the three existing race regressions, and the new isolated-origin encounter browser witness run through `npm test` and `npm run test:browser`.
- [Frozen public fixtures and provenance](../evidence/first-encounter-002/provenance.json) contain native HOLD, REFUSE and ADMIT records with public trust inputs and public native receiver journals. The generator verifies native response signatures, checks inert RECEIVE before automated disposition, and reopens each native receiver from durable files. This reopen is a new receiver instance in the generator process, **not** a claimed fresh-process native journal replay or independently acquired source history.
- [Browser result](../evidence/first-encounter-002/browser/result.json), [mobile screen](../evidence/first-encounter-002/browser/receiver-mobile.png), and [desktop screen](../evidence/first-encounter-002/browser/visitor-desktop.png): two isolated automated Chromium processes on different loopback origins verify the REFUSE packet; their projections equal a fresh Node process reading frozen files. Wrong independent pins reject; pin changes reset approval; delivery requests, browser storage entries and page errors remain zero.
- Negative checks reject missing/substituted trust, embedded trust, changed exact text, foreign signed returns, tampered receipts, wrong crossing/source, malformed native records, unsafe origins, private-key fields, extra secret-bearing fields, oversized input, expiry/revocation of pending proposals and malformed time/revocation bases. This preflight does not test a real HTTPS edge's authorization, replay store or human controls.

Native modules are byte-pinned to the protocol/receiver sources represented by reLATTE PR #62 at `ae3fd0f56860683245dfd27ff32edf64311046bf`. `tests/generate-encounter-fixtures.mjs` checks all four module hashes before importing them. Temporary host-local receiver and independent visitor signers are deleted in a finally block; only public outputs are committed. Normal tests never regenerate keys. Regeneration creates new fixture identities; deterministic cold replay means replaying the **same frozen bytes**, not reproducing random keys.

1. Review the [authenticated-edge security contract](superpowers/specs/2026-10-07-first-encounter-002-design.md). Implement it on a separate reviewable branch, retaining reLATTE's native receipt/receiver ownership. Do not expose or tunnel the existing unauthenticated loopback fixture. Exercise invitation authorization, atomic single-proposal redemption/idempotency across crashes, hostile origins, owner CSRF/authentication, quotas, peer allowlists and journal recovery before public availability.
2. Identify two operator-authorized HTTPS world origins and protected local configurations. Generate independent host-local signing identities there, keeping private keys and redemption/owner credentials out of GitHub, logs and browser storage. No endpoint or private operator configuration has been supplied for this slice.
3. A issues a bounded source-bound invitation; B independently checks A's pin. B explicitly dispatches one signed public-text proposal through the authorized edge. A verifies RECEIVE as inert pending custody, then explicitly chooses one local HOLD / REFUSE / ADMIT. B independently verifies the returned disposition against the exact locally retained proposal and A's separate pin. No transport ACK or timeout admits anything.
4. Record the encounter on two actual participants' separate devices/networks. Acquire their two histories separately; restart and cold replay each host from its own durable records. Perform a second bounded invitation with deliberate REFUSE and test lost/conflicting retries. Publish only redacted witness material that both humans explicitly authorize. Automated browsers or fabricated clicks do not satisfy this gate.
