# USE-FIRST-001 — First public capability shelf

## Thesis
The first adopter does not need a GitHub account, a repo map, or an ontology of the whole machine. **Help them complete one task.** Ship plain-language actions in the already portable Switchboard deployment; do not build another hosting system.

## Verified at implementation time (October 29, 2026)
- **Haunted Toaster:** the latest published GitHub Release is the August 14 `v0.5.0-alpha.8` Windows x64 prerelease, with an approximately 212 MB portable and installer file. It is **unsigned**. The October beta PR is not a publicly released beta package. Links on the shelf point directly to the official assets.
- **WebZ Commons/Jubilee/Wallet/Receiver:** static/browser components already bundled by `apps/build.mjs`. These are **prototypes or printable kits** with explicit local-only limits, not matching services, authority or consenting partner enrollments.
- **Existing Switchboard:** publishes 24 historically inventoried Vercel project doors, including restricted and repair states, and a separate 89-project source atlas. Existing directories remain available; they are **not** a substitute for task-first product entry.

## User-first playbook
1. Begin with **make a music video**, the clearest downloadable application with an artifact a person can produce independently.
2. Have **five real people outside our engineering context** try an ordinary first task on their own computers; ask first and obtain permission to observe. Do not claim this happened until it does.
3. Measure *completed export* and *time / blockers / device compatibility* separately from page views, GitHub download counts, and test suite passes. Collect only voluntary feedback; no tracking code is installed.
4. Make one excellent 60–90-second silent walkthrough and a sample input/output **with material rights confirmed**. Then invite musicians, worship bands, community artists and media classrooms to try it.
5. Prepare a source-owned install/upgrade/licensing statement. The Haunted Toaster app manifest currently specifies `UNLICENSED`; public source availability is **not** an explicit broad open-source license. Resolve user/redistribution terms before claiming unrestricted replication or widespread institutional deployment.
6. Once enough real completions are observed, promote the next most usable capability from source experiment to one-click or download-ready delivery, again with tests and honest labels.

## Why not make every tool a public app immediately?
Source exists at different maturity levels. Some projects are internal kernel infrastructure, others are working experiments with substantial operator setup, and some have finished UI/tool packages. Calling all of them 'ready to use' would break trust. Maintain three distinct status classes in future iterations: downloadable application, browser prototype/kit, and source experiment only. An actual real-world program requires a separate steward and field outcome.

## Deployment
`apps/use/` is copied unchanged into `apps/dist/use/` and linked from the existing Switchboard primary hero. The current Vercel domain and GitHub Pages portable output are unchanged in configuration. A draft PR is **not** a live deployment. The normal independent Pages release workflow can publish after a reviewed mainline merge, but never automatically as part of this draft.

## Next measurable hypothesis
At least one stranger, without a call with the author, can download the signed-or-clearly-unsigned alpha from the official release, provide their own authorized song, generate a satisfactory video on their own hardware, and describe where they got stuck. Until observed, this is an acquisition hypothesis, not evidence of adoption.
