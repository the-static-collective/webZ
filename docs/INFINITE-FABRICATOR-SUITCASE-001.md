# INFINITE-FABRICATOR-SUITCASE-001 — The Living Suitcase Gets a Physical Output Port

**November 1, 2026 · Draft child of [RECURSIVE-WORKSHOP-001](./RECURSIVE-WORKSHOP-001.md) / [MIT Blueprint Foundry](./MIT-SOLVE-2027-BLUEPRINT-FOUNDRY-BASELINE.md) · Software-only, offline, HOLD. No MIT application submitted.**

## The crossing

The playful request was: "Welcome to Infinite. Make me a thing." A Star Trek replicator and a cigarette-making machine are the theatrical inspiration, **not a manufactured device, commercial tobacco plan or an authorized recipe**. Tobacco and consumables are excluded from this proof. The useful kernel is a portable, general **physical output port**: an application can propose an artifact for an explicitly declared local machine, preserve unresolved materials and rights, and wait for a separate owner to authorize one act. Not every object is printable or safe.

```text
Human intention / Full Measure optional quest
  → Infinite / Static Workbench proposed work surface (not integrated here)
  → Living Suitcase / JAR;VIS request and local resource question
  → INFINITE-FABRICATOR-001 source-linked held recipe
  → GHoT advertised machine capabilities (NOT machine connection)
  → STATIC OS CAD / print preparation (separate owner, not invoked here)
  → reLATTE independent owner HOLD / REFUSE / separately admitted permission
  → qualified human supervised machine-local physical act (NOT EXECUTED)
  → actual object + measured independent inspection (NOT OBSERVED)
  → Blueprint Foundry independent second build (NOT REPRODUCED)
  → optional Full Measure reviewed world consequence (NOT CREDITED)
```

## What this branch actually executes

`bridge/mit-solve/infinite-fabricator.mjs` calls the **existing actual** `proposeNextCapability()` module from RECURSIVE-WORKSHOP-001. It does not reinvent that parent or import/simulate GHoT/reLATTE execution. It emits a SHA-256 integrity-addressed, typed `abundent/infinite-fabricator-suitcase-proposal-v1` candidate that binds the parent card by its exact hash.

Three small prototypes, each explicitly HOLD-only:

| Candidate | Tool class | What is real | What is not |
| --- | --- | --- | --- |
| `field-card` | paper printer | An offline software proposal and a paper-first manual alternative | No actual layout, connected printer, event enrolment or printed artifact |
| `case-insert` | FFF 3D printer | An offline bounded proposal derived from the existing body goal | No measured CAD, slicer run, compatible profile, electrical approval or printed insert |
| `alignment-jig` | FFF 3D printer | A proposal derived from the existing printer fixture goal | No calibration, generated jig, machine action or inspection |

A caller may **declare** `paper_printer` or `fff_printer`; this only changes the HOLD reason from missing candidate tool to unresolved machine-owner authorization. The declaration is not independently probed or attested. Unrecognized object and tool types, repeated tools, and unsafe requests are rejected instead of treated as arbitrary instructions. No network request, file write, G-code, print command, payment, inventory debit, verified human witness, Deed or other external effect is emitted.

Run from the repository root:

```sh
node --test tests/infinite-fabricator.test.mjs
node --input-type=module -e 'import {proposeFabricatorObject} from "./bridge/mit-solve/infinite-fabricator.mjs"; console.log(JSON.stringify(proposeFabricatorObject("field-card",["paper_printer"]),null,2))'
```

## Why this belongs in the MIT Suitcase — and where it does not

The original MIT claim remains **Living Suitcase / Blueprint Foundry: Build one. Teach another.** The first target is a real offline-capable computer/phone/router node, built from safe reclaimed equipment, independently tested and then independently reproduced. The new physical-output port is a proposed *successor*: once the computing node is functional, a human could use a nearby ordinary printer to make an invitation card or a carefully reviewed low-consequence removable hardware fixture.

This makes the "Infinite" product insight visible without broadening MIT's first required proof: **applications can become instructions for material artifacts, which may become inputs to subsequent work**. A measured, independently witnessed object can later participate in Mattercraft, Full Measure and downstream community work; mere existence of a recipe cannot.

### Next smallest real pilot, not yet performed

1. Show the real machine and make a private inventory; consent to its use.
2. Print a *blank non-sensitive paper card* manually or with owner permission, recording paper, ink, time, and actual output. A no-device alternative stays usable.
3. Capture an independent reading of the card and whether it was legible; record failures and costs, not just success.
4. A different operator makes a fresh copy from a versioned packet without depending on the first printer or first operator's privileges.
5. Only later consider a non-load-bearing physical insert with real CAD measurements, safe machine-specific settings, supervised actuation, and independent second-build checks.
6. Do not promote a physical-reproduction claim, cost-saving result, credit or labor value until independent evidence exists.

Keep the application and potential funding criteria honest. MIT Solve may exclude concept-stage projects. Running the composer or publishing this door **does not** prove an integrated hardware prototype or meet the challenge's eligibility requirement.

## Boundaries

```text
DECLARED TOOL != CONNECTED MACHINE
RECIPE != PRINTED OBJECT
FILE HASH != PHYSICAL TRUTH
MACHINE CANDIDATE != OWNER AUTHORIZATION
PRINTED OBJECT != FUNCTIONAL SYSTEM
ONE WORKING BUILD != REPRODUCIBLE BLUEPRINT
GAME QUEST != HUMAN COMMITMENT
WORLD RECEIPT != COMMUNITY BENEFIT
```

Source components remain independently governed. The Suitcase does not gain permission to run another project's software or machine by naming it. The Full Measure/Static Workbench linkage is a proposed UI/participation seam, not a fully wired RPG fabricator. This PR should remain draft, stacked on the MIT research branch, and must not be merged into the separate Voqal Still Here pilot as a requirement or safeguarding substitute.
