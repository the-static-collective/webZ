# BRIDGE-001 — BETWEEN ROOMS
**The proposal is the first bridge.** Public prototype dated 2026-10-28.

[Open the public proposal room](../bridge/) · [machine-readable proposal model](../bridge/model.mjs) · [existing Commons receiver](../commons/inbox/) · [Link Wallet](../commons/wallet/)

## Problem and invention
Institutions routinely have adjacent needs but incompatible workflows, permissions, funding rules and evidence standards. A pitch deck is usually disposable. BRIDGE-001 makes **the pitch itself a portable, human-reviewable coordination object**: every potential recipient sees the same original public-safe problem, source provenance and unresolved gates, expressed as a separate, tailored invitation.

A door is **an offer to discuss a bounded crossing**, never a claim of participation. An institution's inclusion, website URL, funding opportunity or public contact detail is **not consent, endorsement, partnership, invitation, funding or data access**.

We should be able to walk into nine different institutions with nine relevant asks, and leave each with a reference to the same reconstructible case **without allowing any institution to control another**.

## The demonstration case
**SYNTHETIC-FOOD-ACCESS-001**: a fictional locally governed food-access group is considering a two-hour public information table and evaluating sourcing, participation and reusable practices. No resident or customer records are required.

A possible field successor is Waseca food access. The local steward, provider, host and independent reviewer are **NOT IDENTIFIED OR AUTHORIZED BY THIS DEMO**. No distribution, municipal cooperation, Ghana transfer or homelessness service has occurred through this proposal.

The visitable room at `bridge/` offers:
1. A source-pinned public description of the core work and eight owner-local phases: LISTEN → MAP → INVITE → RECEIVE → ACT → REPORT → VERIFY → RETURN.
2. Nine **prospective** institutional doors with differing alignment, specific request, offered demonstration and human permission gate.
3. Local-only download of a machine-readable `abundent/bridge-invitation-v0` JSON draft for each potential recipient, and copyable introductory text for human inspection and explicit manual delivery.
4. A fictional recipient HOLD / REFUSE / ACCEPT_FOR_LOCAL_REVIEW rehearsal, exporting `abundent/bridge-rehearsal-v0`. It is **not signed**, **not sent**, **not stored** and **not a real participant disposition**.
5. Source links to the existing JAR;VIS, planZ, reLATTE, webZ Commons, Link Wallet, GRAFT, Garden and Jubilee artifacts.

### One-minute demonstrator
- Open `bridge/` and state the fictional food-access problem.
- Select the rural grocery door: show why an operator-defined problem matters.
- Select MIT Solve: show the same packet reinterpreted for economic resilience, and the functioning-prototype gate.
- Select Cities Deliver: demonstrate the missing authorized organization + city letter, not a fabricated partnership.
- Press HOLD, export the fictional review record, then open the Living Inbox and explain that **only an actually authorized owner** could invite a human counterpart.
- The result shown here is **one real public portable proposal interface**, not a live institutional network.

## Proposal wire contract
`model.mjs` exports `proposal`, `doors`, `invitationFor(id)`, and `draftFor(id)`.

A draft invitation contains only public, organizational-level information:
- Immutable proposal ID and version; prospective target; explicit DRAFT_NOT_SENT classification.
- Scope-specific purpose, request, offered value, human review gate and source URL.
- Fictional sample case and explicit no-personal-data flag.

No credentials, invitation bearer URLs, personal contacts or confidential organization details are exported. The bridge is **not a registry of enrolled partners**. There is no automatic recipient discovery, outbound messaging, money routing, service placement or report verification.

## Required crossing after the public demo
The first real project should be chosen **by a willing local steward**, not by this web page. Minimum viable external pilot:
1. Obtain written permission from the actual organization and host; record scope and authority owner.
2. Let them name one real nonurgent, public-safe coordination issue; use only an approved public-safe description.
3. Confirm communication and review permissions, privacy policy, retention horizon and withdrawal route independently.
4. Give each invited receiver its own bounded role; never publicly expose owner/reviewer/submitter bearer links.
5. Obtain an explicit local disposition; execute only actions independently authorized by the relevant source and receiver.
6. Separate claimant report from independent recipient confirmation. Keep unverified and refused work visibly unresolved.
7. Ask the owner for permission before publishing even a sanitized method.
8. Evaluate success, cost, errors and failures with no reliance on invented outcomes.

**Acceptance gate:** one steward authorized, one bounded invitation received, one genuinely independent reviewer screened, one physical or administrative outcome separately confirmed, and at least one actual source/receiver refusal tested. Until those gates close, the project remains a public **proposal and simulation**.
