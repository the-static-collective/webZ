# LIVING RECEIVER 001 — A locally governed, portable door

**28 October 2026. Working browser-only review instrument. Synthetic examples; not a live Ghana/Minnesota partner network.**

## The field loop

1. **Prepare:** An organization or community steward chooses a public, non-sensitive organizational need in Porchlight Commons. The source card is HOLD, not an approved match or evidence of permission. JAR;VIS may separately prepare a planZ return candidate, itself explicitly unverified.
2. **Receive:** A local steward uses the Living Receiver page (commons/receiver/) to open a small JSON file or paste JSON; it is validated in the browser. Only exact known schemas are accepted and dangerous authority claims are rejected. No upload, account, network or automatic persistence.
3. **Decide:** A human may record HOLD, REFUSE, or ACCEPT_FOR_LOCAL_REVIEW, with role and a non-sensitive reason. These are **self-attested, unsigned** organizational review notes, not P-256-signed reLATTE R3 ADMIT receipts. An acceptance authorizes **nothing beyond continued discussion**; no dispatch, procurement, donation, money transfer or partner enrollment is inferred.
4. **Report:** An accepted-for-review source can generate a REPORTED_PARTIAL, REPORTED_COMPLETE or BLOCKED field-report *claim*. Reports never assert verified outcomes, independent recipient confirmation, source-owner approval or Full Measure accomplishments.
5. **Return:** Download the decision or report JSON and hand it back through a separately agreed channel—email, messaging, USB, print. Another participant can open it in the same reader as a read-only claim without installing our software. No permanent storage is offered by this page; exported files are the operator's responsibility.

## Trust and future integration

The portable contracts have source-packet content digests but **no signature or remote identity verification**. The content digest is not a signer identity, reviewer permission, or actual recipient verification. These web packets are not automatically imported into planZ's source-owner triage and must not be mistaken for reLATTE-signed receipts.

The separate [reLATTE signed transport](https://github.com/the-static-collective/reLATTE/blob/main/docs/PLANZ-RETURN-TRANSPORT-001.md) can transport **validated planZ return candidates** as source-key-signed **claim** observations, with destination-local HOLD/REFUSE/ADMIT. Deploying authenticated source keys and local receiver operators remains future work. Full Measure's [Commons Return Lens](https://github.com/the-static-collective/Full-Measure-World-Layer/blob/main/docs/COMMONS-RETURN-LENS-001.md) grants no Deed/Harvest/Capacity from those foreign observations.

Privacy: This page rejects common PII patterns and caps payload sizes, but filtering is imperfect. **Never paste client records, contact information, restaurant remittance details, sensitive shelter locations, or beneficiary identities.** Do not use this prototype to place people into housing or exchange medical/case records. Files stored by others are governed by those persons' existing device and organizational policies.

## Test it

1. Open the public commons/receiver/ route.
2. Select **Try a clearly synthetic sample**, inspect the need, choose HOLD and enter a non-sensitive reason; export the response.
3. Re-import the response file to show that the receiver can inspect a previous unsigned decision without account creation.
4. Reload the page: unsaved tab state is gone by design. Re-import your downloaded file to continue reviewing.
5. For actual aid, use established local organizations' consent, food-safety, volunteer and recipient-confirmation procedures. No real partner is enrolled or confirmed by this code.

**Constitution:** REQUEST != AUTHORIZATION; IMPORT != AUTHENTICATION; ACCEPT_FOR_REVIEW != ADMIT; REPORT != CONFIRMATION; RECEIPT_OF_BYTES != RECEIPT_OF_BENEFIT.
