# VOQAL-016 — Nourish Kids first: one dinner, then another table

**Review-only, October 29, 2026.** No actual child-feeding program, field delivery, household enrollment, nutrition counseling, institutional endorsement, Coalition sponsorship or Voqal submission. This is one optional practical doorway in the proposed father-first six-month Still Here / Second Table fellowship—not a new funded organization.

## What we dug up

**July 26, 2026:** In the BananaGram → Garden origin conversations, the applicant wanted an instrument that could get *literal oatmeal to children*, not merely move fictional offers, economic abstractions or digital credits. Household-confirmed fulfillment and append-only truth were proposed as conditions of success, not evidence anyone had yet been fed.

**August 1, 2026:** Nourish Kids was explicitly connected to children actually receiving food. An August source atlas recorded the repository as a pantry-based meal-planning app scaffold. This is historical project motivation, NOT confirmed meal delivery.

**The current repository** is [Nourish-Kids](https://github.com/the-static-collective/Nourish-Kids). Its README describes family grocery budgeting, five-staple recipes, a seven-day family plan, support-resource pointers, and an optional Gemini idea assistant. Its prices and illustrative menus are not verified current nutrition or price recommendations. The optional AI must never issue authoritative local availability, child-feeding, medical or food-safety claims.

**The software got more precise in September.** The independent draft [FULFILLMENT PR #2](https://github.com/the-static-collective/Nourish-Kids/pull/2) introduced ten reviewed recipe contracts, available/missing/unknown declarations, quantity and unit checking, and a *selected-only* unmet fulfillment envelope. Draft [RETURN PR #3](https://github.com/the-static-collective/Nourish-Kids/pull/3) admits a bounded status-return projection without rewriting the family's original request; draft [RELEASE-WINDOW PR #4](https://github.com/the-static-collective/Nourish-Kids/pull/4) keeps offer, held, attempted, partial and fulfilled separate. These are independently authored source boundaries, not one deployed integration.

## First human-scale experiment

**Tonight's meal → one specifically identified shortage → voluntary, authorized community response → independently confirmed real outcome → optional independently governed second table.**

A caregiver decides what to make, what is known or unknown, and whether they want help. A source-defined unknown must stay unknown. If they choose to discuss one missing resource with an authorized steward, disclose ONLY the caregiver-chosen resource. No private pantry inventory, child name, age, address, diagnosis, legal/family detail or eligibility record is published or automatically transmitted. A family may use an existing food shelf, WIC/SNAP or other actual service independently; no invented eligibility or partner relationship.

Qualified food safety, dietary suitability, child safeguarding and disability-access review must precede any real-world handling. Nothing here directs infant nutrition or implies a software recipe is clinically approved. Decline and failure are recorded as such, never scoring a household's deservingness.

This is deliberately broader than one meal: food is a concrete first door, but music, repairs, crafts, community growing and neighbor assistance remain voluntary alternative entry points. No child must participate in a study or disclose identity.

## Actual source-native code demonstration

A **new WebZ adapter** at scripts/voqal-nourish-native.mjs invokes three actual original source owner modules from exact Nourish-Kids PR #2 head **669d9750d62c670cfd3894fcffe367af83e85374**: reviewedRecipes.ts, evaluate.ts, and envelope.ts. GitHub Actions checks that pinned Git SHA before executing Node 22's TypeScript stripping feature. The adapter deliberately constructs fictional declarations: first recipe's first ingredient known present, second explicitly absent, third left undeclared/unknown. It asks the original source to compute availability and export ONLY the selected missing requirement as status **unmet**. It asserts zero real families, children fed, pantry delivery, institutional contact, and application submission.

Local reproduction (read-only, fictional):

1. Check out https://github.com/the-static-collective/Nourish-Kids at commit 669d9750d62c670cfd3894fcffe367af83e85374.
2. From this WebZ branch, run: node --experimental-strip-types scripts/voqal-nourish-native.mjs /path/to/pinned/Nourish-Kids
3. Inspect the result: unknown is preserved, unmet is not fulfillment. The original Nourish source is executed, but WebZ does **not** become a real Nourish/Garden/Coalition fulfillment service.

The public static review page bridge/first/nourish-kids.html executes **no JavaScript** and is not an intake or operational meal-planning application. Native execution is instead in the executable/CI with source-owned modules. A successful hosted test establishes synthetic software behavior only.

## Fellowship planning / budget — no added commitment

Use **existing** $30,000 proposal categories: low-cost shared meals, paid caregiver/resident co-design, independent professional safeguarding/access review, participant transport and legitimate host permission. Do not add a new budget line, pay leaders for access or substitute festival production for food assistance. Local food-shelf and co-op stakeholders are potential listeners; five in-person encounters and Coalition of Care core-team membership are firsthand applicant claims, not authorization, support or partner enrollment.

**April:** seek caregiver-led feedback and authorized institutional critique, commissioning paid food/access review. **May–June:** if safe and consented, hold one table testing one concrete meal problem and one owner/recipient-confirmed useful return. **July–August:** invite voluntary small follow-up tables; determine whether interested residents can carry the method without the originator, and record refusals. **September:** honestly publish public-safe learnings, not a fabricated child-feeding count. Other pilot stations and a conditional closing event continue under their existing gates.

**Social falsifier:** The first table cannot be made safe, accessible and independently useful, or a second group cannot freely adapt or refuse without founder approval. Software correctness does not refute a human failure.
